# Prompt: make or change an Excalidraw board (for an agent with a shell)

How to use this: give an agent that can run commands in a checkout of this repository the text below the line, with what you want drawn filled in where it says `<WHAT>`.

----------------------------------------------------------------------------------------------------

You are working in a repository whose design drawings are Excalidraw boards that are **generated by programs**. Read `AGENTS.md` in the repository root first and keep its rules. Then make this: **<WHAT>**.

## Read, in this order

1. `excalidraw_generator/EXCALIDRAW_GUIDE.md`: sections 2 (commands), 3 (how to think about it), 5 (the widgets), 6 (the design rules, which you must keep), 9 (definition of done), 10 (things that bit the last author), and 12 (the JSON route).
2. `excalidraw_generator/examples/hello_board.py` and `examples/add_a_screen.py`, if you will write Python.
3. `python3 excalidraw_generator/board_spec.py describe`, if you will write JSON.

## Choose the route

- **A new board, or screens made of the fifteen items** (heading, text, caps, card, button, chip, bar, placeholder, mark, table, checklist, key/value, box, arrow, callout): write the board as JSON (`reqin-board/1`) and compile it. This is the faster route and the checker finds layout mistakes for you.
- **A change to an existing board, or something the fifteen items cannot draw**: write Python, following recipe A or B in the guide, and `build_all.py`.

Never edit a `.excalidraw` file by hand.

## Commands (from `excalidraw_generator/`)

```
python3 board_spec.py check   spec.json                            # every problem at once, with its path
python3 board_spec.py build   spec.json out.excalidraw --strict --png out.png --scale 2    # warnings fail the build
python3 build_all.py --out ../excalidraw && python3 validate.py ../excalidraw/*.excalidraw   # the Python route
```

The picture needs Node and a Chromium (see guide section 2). If you cannot make a picture, say so: you have then not looked at the result, and you must not say the board looks right.

## Rules

- Sample data only. No real programme, customer or person names, no text copied from a real requirements document.
- Keep the design rules in the guide's section 6: grey is structure, a state is always also a word, one primary button per screen, marks keep their meanings, every frame has callouts and notes that say **why**.
- Do not change boards you were not asked to change. After a Python change, `python3 build_all.py --check --out ../excalidraw` must say `identical` for the others.
- Do not push, and do not change a remote or any CI setting.

## Done means

1. The build exits 0 and `validate.py` reports `dup 0 dangling 0 frame-order 0 outside 0` (or each overflow is explained).
2. For the JSON route, `check --strict` says `ok` with no warnings.
3. **You looked at the picture** of every frame you made or changed: text fits, nothing overlaps, each callout number matches its note.
4. `python3 -m pytest -q tools` passes (it checks that board pictures in `docs/images/` match their boards, so after a change to a committed board, run `python3 render_previews.py` and look at the result).

## Report

What you made, where the files are, the commands you ran and what they said, what you saw in the picture, and a list headed **Not checked** (the live Excalidraw app, any other browser, anything you could not run).
